## 現有程式的確切行為

1. `CaptureQuality.ready` 要求至少三面牆、八張照片及 85% 照片覆蓋率。這是品質提示，不是保存的必要條件。
2. `CaptureScreen` 顯示的百分比代表已觀測表面的照片覆蓋率，不代表整個房間完成度。局部場景可能不會滿足三面牆的提示。
3. 掃描畫面已提供 `Save room`；`finishRoom()` 不檢查上述品質門檻。因此不能把問題簡化成「解除保存門檻」。如果按保存後卡住，須檢查照片寫入、網格匯出及 RoomPlan 結束回呼。
4. `CaptureBudget` 在照片數達 150 或溫度／記憶體受限時降低頻率，但沒有因此停止自動拍照。
5. 原 skill 已要求保留座標轉換、相機位置、內參及原始像素方向；跨 session 的房間名稱相同，不代表已對齊。

## 可選方向

| 方向 | 優點 | 代價 |
| --- | --- | --- |
| A. 混合重建（建議） | 掃描提供尺寸與位置，img2threejs 重建個別物件；可分階段檢查 | 需要挑選照片與逐件建模，不能保證一次完成 |
| B. 只修掃描與保存 | 保留既有流程，改動較集中 | 若破碎來自座標、輸入品質或重建方式，仍需另外修正 |
| C. 只用照片建模 | 可跳過掃描等待 | 比例與遮擋面需推估，無法當成完整實測空間 |

## 建議第一版：方向 A

### 手機擷取

- 明確區分「局部擷取」與「完整房間」；局部擷取不以三面牆作為品質提示前提，缺少尺寸時標記未量測。
- 提供固定可見的「保存目前結果」。將照片覆蓋顯示為補拍參考，避免讓使用者等待自動完成或追求 100%。
- 自用模式先採每房間 60 張自動照片的可調初始預算；這是控制資源的設計值，不是重建品質保證。達預算後停止自動拍照，允許手動補拍，不刪除既有照片，也不自動結束 RoomPlan。
- 保留既有追蹤品質與熱負載控制，將取得資料、照片數及缺少視角分開呈現。
- 保存時顯示實際階段。若原始紀錄確認某階段卡住，才為該階段設計可安全取消／重試的恢復流程；不能只在 UI 計時後假報成功，亦不能丟棄仍在寫入的資料。

### 輸入檢查與參考照片

- 先讀取原始 zip 中的 `manifest.json`、房間 JSON、`photos/photos.json`、照片與 `diagnostics.json`（若有）；原始輸入保留不變。
- 核對實際照片數、檔案完整性、相機內參／姿態、影像方向、session 及對齊狀態。沒有姿態的普通照片只能當視覺參考。
- 依清晰度、曝光、視角與空間覆蓋挑選工作用照片，另存保留與排除理由。不能只按檔案順序截取固定張數。
- 對齊不足的 session 分開檢查，不能混成一個房間，也不從房名推斷座標。
- 先在無貼圖狀態檢查幾何，再檢查投影貼圖，區分網格破碎、座標錯位與照片投影問題。

### 兩個 skill 的分工

1. `scan-to-threejs`：匯入可靠的量測、建立地板／牆面／門窗與物件位置，統一為公尺、Y 向上及同一房間座標。
2. `img2threejs` 公開 `generic` profile：每次處理一個主要物件，以清楚參考照片和已知尺寸建立 Three.js Group；每個物件有自己的 spec、state 及比較紀錄。
3. 物件先做外形、比例與擺放，再做材質細節。採用 skill 原有分階段檢查與有上限的修正流程，不把失敗報告改成通過。
4. 以適配層將物件的原點、軸向及尺度轉換到 RoomModule。保留每個部件的來源與量測／推估標示。
5. 在原 viewer 的相機比對工具中，用數個可靠拍攝視角檢查房間與家具；只有俯視圖或單一漂亮角度不足以驗收。

img2threejs 是照片引導的程式建模 skill，不是照片測量引擎，也不是在 iPhone 內執行的掃描 SDK。公開基礎 skill 不包含完整房間自動重建能力；官方的 `environment` 外掛需要私有 GitHub 存取，本版不依賴它。看不到的物件背面與未量測尺寸必須標記推估。

## 安裝與跨機器安排

Mac 是 iOS 編譯與實機驗證環境。img2threejs 官方 CLI 目前支援 macOS／Linux，尚未宣告 Windows 支援。Mac 需 Node.js 18 以上、Python 3.10 以上及 Git；本專案 viewer 的 Node.js 要求較高，採原專案的 22.12 以上。

Mac 上可針對 Codex 安裝公開基礎 skill：

```sh
npx --yes img2threejs@latest install --host codex
npx --yes img2threejs@latest doctor
```

依官方說明重啟代理工具，確認實際載入版本後，記錄版本與 commit。此文件沒有執行安裝，也沒有安裝私有外掛。

整合變更完成後再同步至使用者的 GitHub fork，讓 Mac 拉取；私人照片、原始匯出與診斷結果維持在被 Git 忽略的資料夾，不隨公開原始碼上傳。保留 MIT 原始碼授權，以及 img2threejs 的 Apache-2.0 授權和來源資訊。

## 驗收

- 局部擷取：一至兩面牆也能主動保存；UI 不將照片覆蓋率描述成房間完成度。
- 照片預算：到達預算後自動拍照停止，手動拍照仍遵守原本追蹤與寫入限制。
- 保存：實機可完成新掃描、已有兩百多張照片的掃描與暫停後保存；失敗時顯示真實階段並保留已寫入檔案。
- 匯入：損壞／缺失姿態及跨 session 未對齊資料有明確報告，不能假設對齊。
- 建模：先以使用者一個失敗房間中的一件主要家具驗證完整流程，再擴大到整個房間。確認尺度、位置、各視角外形與材料。
- 執行適合變更的政策測試、iOS 編譯、viewer build 與視覺比對；Windows 靜態檢查不能代替 Mac／iPhone 實機結果。

## 後續診斷需要的資料

原始失敗房間匯出 zip（包含 metadata，不能只有 JPG），以及 iPhone 型號、iOS 版本和目前 App 版本。若破碎結果是另一個重建工具產生，也須記錄工具名稱與其輸出。這些資料用來確認根因及驗收，並非要求重新拍兩百張照片。
